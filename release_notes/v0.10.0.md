# Release Notes - v0.10.0

**Date:** 2026-09-15

## Overview

v0.10.0 reworks categories to follow the MediaWiki model.
Every category now has a single page in the Category namespace that shows its description together with the pages in the category, and the Category namespace page lists every category in use.
It also fixes RST categories missing from Special:Categories and adds `make start-bg`.

This is a minor release because category URLs change; old links redirect automatically.

---

## Changed

### One page per category, in the Category namespace

Tag a page with `[[Category:Fruit Dishes]]` (or `.. category:: Fruit Dishes` in RST) and the category's page is:

```
/wiki/Category/fruit-dishes
```

That page shows:

- the category's **description**, if one has been written, with **Edit description** and **History** buttons (or **Add description** when there is none);
- the **pages in the category**, alphabetically, grouped by first letter.

Previously the member list lived at `/category/Fruit Dishes`, and the description was a separate page at `/wiki/Category/fruit-dishes` that showed no members.

- Adding or editing a description returns you to the category page.
- Old `/category/<name>` links and bookmarks redirect permanently to the new URL.
- Category links on pages, the wikitext category footer and Special:Categories all use the new URL.
- Categories are matched ignoring case and spacing: "Fruit Dishes" and "fruit dishes" are the same category.
- A category with no tagged pages and no description returns "not found", with a hint on how to create it.

### The Category namespace lists every category

`/wiki/Category` now lists every category used anywhere on the wiki, with its number of pages and whether it has a description (logged-in users get an **Add** link for undescribed categories).
Before, it only listed the categories someone had written a description for, so it usually looked empty.

No pages are created automatically: as in MediaWiki, a category exists as soon as a page is tagged, and its description page is only stored once someone writes one.

---

## Added

- **`make start-bg`** runs the server in the background, logging stdout and stderr to `/tmp/$APP_LOG`.
  Set `APP_LOG` in `.env` to choose the file name (default `pywiki-<APP_PORT>.log`).
  It replaces `make run`.

---

## Fixed

- **RST categories on Special:Categories** - categories declared only with `.. category::` were missing from the list, although their category pages worked.
- **Special pages** - "N categories currently in use" no longer counts categories that only have a description.
- **Makefile** - no `grep: .env: No such file or directory` noise when there is no `.env`; a duplicate `APP_PORT` line was removed.

---

## Upgrade Notes

No database schema changes, no new dependencies and no required configuration changes.

- Existing description pages in the Category namespace become the descriptions shown on their category pages; nothing needs migrating.
- Links to `/wiki/Category/<name>` that used to show only a description now show the full category page.
- `RENDERER_VERSION` is now 17, so pages re-render once on their next view (this updates category links inside wikitext pages).
- If you used `make run`, switch to `make dev` (with reload) or `make start-bg` (background).

```bash
cd /opt/pywiki
sudo systemctl stop pywiki
sudo -u pywiki git pull
sudo systemctl start pywiki
```
