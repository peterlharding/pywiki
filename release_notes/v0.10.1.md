# Release Notes - v0.10.1

**Date:** 2026-09-15

## Overview

v0.10.1 is a housekeeping release with no changes to the running application.
It stops tracking `uv.lock` in git and brings the documentation up to date.

---

## Changed

### `uv.lock` is no longer tracked

`uv.lock` is now listed in `.gitignore`.

PyWiki is installed from `requirements.txt` (development) and `setup/requirements.txt` (servers); neither uses the lockfile.
Instances running different versions of uv kept rewriting `uv.lock` in different formats, so a tracked lock only produced conflicts when pulling updates.
Each checkout can now keep its own local `uv.lock` without it showing up in `git status`.

Dependency changes belong in `pyproject.toml`, `requirements.txt` and `setup/requirements.txt`.

### Documentation

- **README** - covers all three content formats (including wikitext), categories, attachment link syntax for each format, layout and import/export features, and the attachment API endpoints.
- **Server setup guide** (`setup/README.md`) - the first registered account becomes an admin automatically; restarts use `systemctl stop` then `start`; updates stop the service before pulling.
- **Developer notes** (`SKILLS.md`, `CLAUDE.md`) - the fresh-install checklist runs database migrations before the first start (matching the setup guide, so later migrations apply cleanly), and the release process and conventions reflect current practice.

---

## Upgrade Notes

No application, database or configuration changes.

Pulling this release removes `uv.lock` from each checkout.

- If the lockfile on an instance was never changed, `git pull` simply removes it.
- If `git pull` refuses because `uv.lock` has local changes (for example "cannot pull with rebase: You have unstaged changes"), discard the local lock and pull again:

  ```bash
  cd /opt/pywiki
  sudo -u pywiki git checkout -- uv.lock
  sudo -u pywiki git pull
  ```

- Only instances that use `uv sync` need `uv lock` afterwards; the regenerated lock stays local.

No restart is required, but restarting picks up the new version number shown in the footer:

```bash
sudo systemctl stop pywiki && sudo systemctl start pywiki
```
