# Release Notes - v0.7.0

**Date:** 2026-09-14

## Overview

v0.7.0 is a maintenance and deployment cleanup release.
All installation material now lives in a single `setup/` folder, the uvicorn port is configured in one place, and the TLS documentation works for anyone deploying the public repo.
It also fixes a fresh-install failure, broken `attachment:` links with current mistune, and every outstanding lint finding.

This is a minor (rather than patch) release because deployment paths and the systemd unit changed; existing instances need the upgrade steps below.

---

## Breaking Changes

### Setup files moved to `setup/`

| Old location | New location |
|--------------|--------------|
| `deploy/README.md` | `setup/README.md` |
| `deploy/requirements.txt` | `setup/requirements.txt` |
| `deploy/pywiki.service` | `setup/pywiki.service` |
| `deploy/nginx-pywiki.conf` | `setup/nginx-pywiki.conf` |
| `deploy/Makefile`, `deploy/0*_*.sh` | `setup/Makefile`, `setup/0*_*.sh` |
| `sql/grant.sql` | `setup/grant.sql` |
| `scripts/setup-jose.sh` | `setup/setup-jose.sh` |
| `.env.example` | `setup/env.template` |

`docs/deployment.md` (an empty stub) was removed; `setup/README.md` is the deployment guide.

### `pywiki.service` reads the port from `.env`

The unit previously hard-coded `--port`.
It now runs uvicorn with `--port ${APP_PORT}`, taken from `/opt/pywiki/.env`.
An instance whose `.env` has no `APP_PORT` will fail to start once the new unit is installed.

## Changed

- **Port convention** - `APP_PORT` in `.env` is the single source of truth.
  `make dev` / `make run` fall back to `8000` when it is unset.
  Production instances sharing a server use `8` followed by the instance IP's last octet, zero-padded (`10.0.0.222` -> `8222`); nginx `proxy_pass` must match.
- **TLS documentation** - `setup/README.md` and `nginx-pywiki.conf` default to Let's Encrypt (option A) and document bringing your own certificate, such as a wildcard (option B).
  TLS protocol and session settings are now inline, so the config no longer depends on certbot-generated include files and works with either option.
- **`grant.sql`** takes the database name as a psql variable instead of a hard-coded name:
  `psql -d <db> -v db_name=<db> -f setup/grant.sql`.
- **`.gitignore`** still ignores `SETUP/` but re-includes `/setup/`, which otherwise disappeared from git on case-insensitive filesystems such as macOS.
- **Development** - `ruff` added to `requirements.txt`; all ruff findings fixed (import sorting, `X | None` annotations, unused imports and variables).
- **`CLAUDE.md`** added and `SKILLS.md` made platform-neutral.

---

## Fixed

- **Fresh installs failed** - `sqlalchemy` was listed without its `asyncio` extra, so `greenlet` was missing on some platforms and 159 of 295 tests errored.
  All dependency lists now use `sqlalchemy[asyncio]`.
- **Unresolved `attachment:` links rendered as `#harmful-link`** - mistune 3.3 only allows a fixed set of URL schemes.
  The internal `attachment:` scheme is allowed again (dangerous schemes such as `javascript:` remain blocked).
  `RENDERER_VERSION` is now 13, so cached HTML is re-rendered on next view.
- **UI returned 500 when started outside the repo root** - Jinja2 templates were loaded from a path relative to the working directory; they now resolve relative to the package.
- **`setup/Makefile` `setup-venv`** called a non-existent `activate` command.
- **Stale documentation** - references to the deleted `deploy/.env.example` and a non-existent `sql/add_pywiki.sql`; the "Updating" steps used `pip install -e .`, which fails on some servers.

## Upgrade Notes

No database schema changes and no configuration changes are required for the application itself.

For an existing server instance (adjust `/opt/pywiki` and the `pywiki` service name to match yours):

```bash
cd /opt/pywiki
sudo systemctl stop pywiki
sudo -u pywiki git pull

# 1. Record the instance's port in .env (the value the old unit hard-coded)
grep -- '--port' /etc/systemd/system/pywiki.service
grep -q '^APP_PORT=' .env || echo 'APP_PORT=<port from above>' | sudo tee -a .env

# 2. Install dependencies (adds greenlet via sqlalchemy[asyncio])
sudo -u pywiki .venv/bin/pip install -r setup/requirements.txt

# 3. Install the new unit (merge by hand instead if you customised the old one)
sudo cp setup/pywiki.service /etc/systemd/system/pywiki.service
sudo systemctl daemon-reload

sudo systemctl start pywiki
journalctl -u pywiki -n 30 --no-pager | grep -iE 'error|exception'
```

Existing nginx site configs keep working unchanged; adopting the new `nginx-pywiki.conf` is optional.
Update any local notes or scripts that refer to `deploy/`, `sql/` or `.env.example`.
