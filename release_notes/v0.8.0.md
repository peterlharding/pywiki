# Release Notes - v0.8.0

**Date:** 2026-09-14

## Overview

v0.8.0 lets pages carry documents as well as images.
PDF, Office, OpenDocument, CSV, text and Markdown files can be uploaded, linked from page content and listed on the page, and the set of allowed types is configurable in the same way as MediaWiki's `$wgFileExtensions`.
Uploaded files are validated on every upload path and served with defensive headers.

This is a minor (rather than patch) release because uploads that used to be accepted may now be refused, and existing attachments are served with different headers; see Upgrade Notes.

---

## New Features

### Document attachments

The default allowed types are:

`png, jpg, jpeg, gif, webp, avif, svg, bmp, pdf, txt, md, csv, docx, xlsx, pptx, odt, ods, odp`

- **Editor** - the attachment panel accepts any allowed type (drag and drop or file picker), shows the allowed list and size limit, and rejects other files before uploading.
- **Special:Upload** - the file picker is limited to allowed types, and after an upload it shows embed syntax for images or link syntax for documents.
- **Page view** - a new **Files** section lists non-image attachments with an icon, size and delete button, below the existing Images section.
  The "📎 Upload file" page tool now opens Special:Upload for the page.
- **ZIP import** - attachments of disallowed types are skipped and counted in the import banner.

### `ATTACHMENT_EXTENSIONS` setting

```ini
# .env - comma- or space-separated
ATTACHMENT_EXTENSIONS=png,jpg,jpeg,gif,webp,avif,svg,bmp,pdf,txt,md,csv,docx,xlsx,pptx,odt,ods,odp
```

A fixed list of dangerous types is always refused, even if listed: web and script content (`html`, `js`, `php`, `py`, `sh`, ...), executables (`exe`, `msi`, `bat`, `jar`, ...) and macro-enabled Office files (`docm`, `xlsm`, `pptm`, ...).
If the setting names any of these, a warning is logged at startup.

### Linking to files

| Format | Syntax |
|--------|--------|
| Markdown | `[Q3 report](attachment:report.pdf)` |
| Wikitext | `[[Media:report.pdf]]` or `[[Media:report.pdf\|Q3 report]]`; `[[File:report.pdf]]` also links non-image files |
| RST | `` `Q3 report <attachment:report.pdf>`_ `` (unchanged) |

Links to files that have not been uploaded yet render as red upload links in all formats, pre-filling Special:Upload for the page.

## Changed

- **Serving** - the content type comes from the file extension, never from the uploading browser, and every response sends `X-Content-Type-Options: nosniff`.
  Images, PDF, text and Markdown (as plain text) open in the browser; everything else, including SVG and Office files, downloads.
  All types except PDF are sandboxed with a Content-Security-Policy.
- **Filenames** are sanitised on upload (directory parts and characters such as `<>:"|?*` are replaced).
- `RENDERER_VERSION` is now 15, so cached page HTML is re-rendered on first view.

---

## Fixed

- **Attachment links stayed broken after uploading the file** - uploading or deleting an attachment now clears the page's cached HTML, and API page responses render attachment links like the UI does.
- **Internal links opened in new tabs** when `BASE_URL` is an absolute URL (as in production); only external links get `target="_blank"` now.
- **Special:Upload and Move page forms were unstyled**, and form inputs had unreadable text in dark mode.
- **Editor attachment list** built HTML from filenames; entries are now created with DOM APIs.
- **`setup/env.template`** had `MAX_ATTACHMENT_BYTES=52428800   # 50 MB`; under systemd the comment became part of the value and the service failed to start.
- Sidebar "Updated" timestamp no longer splits between date and time.

## Upgrade Notes

No database schema changes and no new dependencies.

1. **Check the allowed types.**
   Uploads were previously unrestricted.
   If your wiki relies on types outside the default list (for example `zip`, `doc`, `xls`, `json`), add them to `ATTACHMENT_EXTENSIONS` in `.env`.
   Attachments that are already stored stay downloadable whatever their type; only new uploads are checked.
2. **Check `.env` for trailing comments.**
   systemd keeps `# ...` after a value as part of it, which breaks numeric and boolean settings.
   Move any such comments onto their own lines:
   ```bash
   grep -nE '^[A-Z_]+=.*[[:space:]]#' /opt/pywiki/.env
   ```
3. **Deploy as usual:**
   ```bash
   cd /opt/pywiki
   sudo systemctl stop pywiki
   sudo -u pywiki git pull
   sudo systemctl start pywiki
   journalctl -u pywiki -n 30 --no-pager | grep -iE 'warning|error|exception'
   ```
   A `ATTACHMENT_EXTENSIONS lists prohibited types` warning means the setting names a type that will be refused.

If you raise `MAX_ATTACHMENT_BYTES` above 50 MB, raise `client_max_body_size` in the nginx site config as well.

## Known Limitations

- Audio and video files can be allowed and attached, but there is no inline player yet.
- The prohibited list is not configurable.
