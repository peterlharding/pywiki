# Release Notes - v0.9.0

**Date:** 2026-09-14

## Overview

v0.9.0 makes PyWiki use the width of large screens.
The layout used to stop at a fixed 1200px, leaving most of a wide monitor empty.
It now grows with the browser window up to a limit based on the reader's own screen, and readers can switch to full width with a toggle in the header, much like MediaWiki.

---

## New Features

### Wide-screen layout

- By default the page layout is limited to **90% of the reader's screen width**, never less than 1200px.
  For example: 2304px on a 2560px monitor, 1728px on a 1920px monitor.
- In a window narrower than that limit, the page fills the window and grows as the window is widened.
- The limit is calculated in the browser before the page is drawn, so there is no visible jump, and it is recalculated if the window moves to a screen of a different size.

### Full / limited width toggle

- A new button next to the dark mode toggle switches between **full width** and the **limited** width.
- The choice is remembered in the reader's browser and applies to every page.
- The button only appears when the window is wider than the limited layout, and not on the editor and user list, which always use the full width.

### `LAYOUT_MAX_WIDTH` setting

Sets the layout for readers who have not used the toggle:

```ini
# .env
#   auto   - 90% of the reader's screen width, never below 1200px (default)
#   full   - fill the browser window
#   <size> - a CSS length such as 1600px, 100rem or 90% (a bare number means px)
LAYOUT_MAX_WIDTH=auto
```

With `full`, the toggle offers the `auto` limit as the alternative.
An invalid value stops the app at startup with an error naming the setting.

---

## Fixed

- **Navbar** - links now sit at the right edge instead of beside the search box, and the navbar spans the full width on the editor and user list so it lines up with the page.
- **Files list** - on wide layouts file sizes no longer sit far away from their names.
- **Narrow screens** - page content now fills the width on phones and small windows instead of shrinking to fit its text.
- **Tests** - the suite no longer reads the developer's `.env`, so local settings cannot change results; tests always use in-memory SQLite.
  The new `PYWIKI_ENV_FILE` environment variable selects a different settings file (or none, when empty).

---

## Upgrade Notes

No database schema changes, no new dependencies and no required configuration changes.
Existing instances get the `auto` layout; add `LAYOUT_MAX_WIDTH` to `.env` only to choose something else (keep any comment on its own line).

```bash
cd /opt/pywiki
sudo systemctl stop pywiki
sudo -u pywiki git pull
sudo systemctl start pywiki
journalctl -u pywiki -n 30 --no-pager | grep -iE 'warning|error|exception'
```

CSS and JavaScript URLs include the version, so browsers pick up the new layout without a hard refresh.
